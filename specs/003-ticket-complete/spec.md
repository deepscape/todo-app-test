# Feature Specification: 티켓 완료 처리

**Feature Branch**: `003-ticket-complete`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "티켓 완료 처리 기능. 사용자는 진행 중인 티켓을 완료 상태로 전환할 수 있다. 완료 처리되면 완료 시각이 자동으로 기록되고, 완료된 티켓은 보드의 완료 칼럼 맨 위에 표시된다. 존재하지 않는 티켓을 완료 처리하려 하면 404 에러를 반환한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 할 일을 완료로 표시 (Priority: P1)

사용자가 진행 중이던 할 일을 끝마쳤을 때, 그 티켓을 완료 상태로 전환하여
"끝난 일"과 "아직 할 일"을 명확히 구분할 수 있다.

**Why this priority**: 완료 처리는 칸반 보드의 핵심 가치(진행 상태를
시각적으로 관리)를 완성하는 마지막 조각이다. 이 기능 없이는 사용자가 끝낸
일을 표시할 방법이 없어 보드가 실제 업무 흐름을 반영하지 못한다.

**Independent Test**: 임의의 상태의 티켓을 하나 준비한 뒤 완료 처리를
요청하고, 그 티켓이 완료 상태로 바뀌고 완료 시각이 기록되었는지 확인하는
것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 완료되지 않은 티켓이 있을 때, **When** 사용자가 그 티켓을
   완료 처리하면, **Then** 티켓의 상태가 완료로 바뀌고 완료 시각이 현재
   시각으로 기록된다.
2. **Given** 존재하지 않는 티켓 id로 완료 처리를 요청했을 때, **When**
   완료 처리를 시도하면, **Then** 티켓을 찾을 수 없다는 오류가 반환된다.

---

### User Story 2 - 방금 완료한 일을 보드 맨 위에서 확인 (Priority: P2)

사용자가 티켓을 완료하면, 그 티켓은 보드의 완료 칼럼에서 가장 먼저 보이는
위치(맨 위)에 나타나 방금 무엇을 끝냈는지 바로 알아볼 수 있다.

**Why this priority**: 완료 칼럼 안에서의 위치는 완료 처리 자체(User
Story 1)가 동작한 뒤에만 의미가 있는 부가적인 사용성 개선이다.

**Independent Test**: 완료 칼럼에 이미 티켓이 하나 이상 있는 상태에서 새
티켓을 완료 처리한 뒤, 보드를 조회했을 때 방금 완료한 티켓이 완료 칼럼의
가장 앞에 나타나는지 확인하는 것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 완료 칼럼에 이미 다른 완료된 티켓이 있을 때, **When** 사용자가
   새 티켓을 완료 처리하면, **Then** 그 티켓은 완료 칼럼의 다른 티켓들보다
   앞쪽에 표시된다.

### Edge Cases

- 이미 완료 상태인 티켓을 다시 완료 처리하는 경우: 완료 시각이 현재 시각으로
  다시 갱신된다 (재완료 처리로 취급하며 오류를 발생시키지 않는다).
- 완료 처리는 이 기능이 다루는 유일한 상태 전이이며, 다른 상태(대기/할 일/
  진행 중) 간 이동은 별도 기능(순서/상태 변경)의 책임이다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 존재하는 티켓의 id로 완료 처리를 요청받으면 해당
  티켓의 상태를 완료로 전환해야 한다.
- **FR-002**: 시스템은 완료 처리 시 완료 시각을 현재 시각으로 자동
  기록해야 한다.
- **FR-003**: 시스템은 완료 처리된 티켓이 완료 칼럼 내에서 다른 기존
  완료 티켓들보다 먼저(맨 위) 표시되도록 위치를 지정해야 한다.
- **FR-004**: 시스템은 존재하지 않는 티켓 id로 완료 처리를 요청받으면
  티켓을 찾을 수 없다는 오류를 반환해야 한다.
- **FR-005**: 완료 처리가 성공하면 시스템은 마지막 수정 시각도 현재
  시각으로 갱신해야 한다.
- **FR-006**: 완료 처리 응답은 완료된 티켓의 전체 정보를 포함해야 한다.

### Key Entities *(include if feature involves data)*

- **티켓(Ticket)**: 001-board-view/002-ticket-detail-crud에서 정의한 것과
  동일한 엔티티. 이 기능은 티켓의 상태를 완료로, 완료 시각을 현재 시각으로,
  칼럼 내 위치를 완료 칼럼 맨 위로 전환한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 완료 처리를 요청하면 1초 이내에 해당 티켓이 완료
  상태로 반영된다.
- **SC-002**: 완료 처리된 티켓은 100% 정확히 완료 시각이 기록되며, 이후
  보드 조회에서 "방금 완료한 일"로 식별 가능하다 (기존 완료 24시간 노출
  규칙과 연동).
- **SC-003**: 완료 처리된 티켓은 완료 칼럼을 다시 열었을 때 항상 가장
  먼저 보이는 위치에 나타난다.
- **SC-004**: 존재하지 않는 티켓에 대한 완료 처리 시도는 100% 명확한
  "찾을 수 없음" 오류로 안내된다.

## Assumptions

- 인증/권한 구분이 없는 단일 사용자 환경이므로, 완료 처리는 소유권 확인
  없이 티켓 id만으로 식별된다.
- 완료 처리는 이전 상태(대기/할 일/진행 중 중 어디였는지)와 무관하게
  동일하게 동작한다 — 어떤 칼럼에 있던 티켓이든 완료로 전환할 수 있다.
- 완료 칼럼 내 "맨 위" 배치는 001-board-view가 이미 정의한 position 규칙
  (해당 칼럼의 최솟값보다 작은 값 부여)과 동일한 방식을 따른다.
