# Feature Specification: 티켓 순서/상태 변경 (드래그앤드롭)

**Feature Branch**: `004-ticket-reorder`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "티켓 순서/상태 변경 기능. 사용자는 드래그앤드롭으로 티켓을 다른 칼럼(대기/할 일/진행 중)으로 이동시키거나 같은 칼럼 내에서 순서를 바꿀 수 있다. 할 일 칼럼으로 이동하면 시작 시각이 자동 기록되고, 할 일에서 대기로 되돌리면 시작 시각이 초기화된다. 완료 칼럼에서 다른 칼럼으로 이동하면 완료 시각이 초기화된다. 완료 칼럼으로의 이동은 이 기능의 범위가 아니다(별도 완료 처리 기능 사용). 존재하지 않는 티켓을 이동하려 하면 404 에러를 반환한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 티켓을 다른 칼럼으로 이동 (Priority: P1)

사용자가 드래그앤드롭으로 티켓을 다른 칼럼(대기, 할 일, 진행 중)으로
옮기면, 그 티켓의 상태가 옮겨진 칼럼에 맞게 바뀌고 원하는 위치에 놓인다.

**Why this priority**: 칼럼 간 이동은 칸반 보드의 핵심 조작이다. 이 기능
없이는 사용자가 할 일의 진행 단계를 전혀 바꿀 수 없어 보드가 정적인 목록에
불과해진다.

**Independent Test**: 대기 칼럼의 티켓을 할 일 칼럼의 특정 위치로 이동
요청한 뒤, 보드를 조회하여 그 티켓이 할 일 칼럼의 지정된 위치에 나타나는지
확인하는 것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 대기 칼럼에 있는 티켓이 있을 때, **When** 사용자가 그 티켓을
   할 일 칼럼의 특정 위치로 이동하면, **Then** 티켓의 상태가 할 일로
   바뀌고 지정한 위치에 놓인다.
2. **Given** 존재하지 않는 티켓 id로 이동을 요청했을 때, **When** 이동을
   시도하면, **Then** 티켓을 찾을 수 없다는 오류가 반환된다.

---

### User Story 2 - 같은 칼럼 내에서 순서 재배치 (Priority: P1)

사용자가 같은 칼럼 안에서 티켓의 순서를 드래그앤드롭으로 바꾸면, 그
순서가 그대로 유지되어 다음에 볼 때도 동일하게 보인다.

**Why this priority**: 칼럼 내 우선순위 재배치는 칼럼 간 이동만큼이나
자주 쓰이는 핵심 조작으로, 사용자가 "오늘 먼저 할 일"을 정하는 유일한
수단이다.

**Independent Test**: 한 칼럼에 티켓 3개가 있을 때 마지막 티켓을 맨
앞으로 옮기도록 요청한 뒤, 보드를 조회하여 순서가 바뀌었는지 확인하는
것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 같은 칼럼에 티켓이 여러 개 있을 때, **When** 사용자가 그
   중 하나를 같은 칼럼의 다른 위치로 옮기면, **Then** 칼럼 내 순서가
   요청한 대로 바뀐다.
2. **Given** 두 티켓 사이에 새 위치를 지정했을 때, **When** 이동이
   처리되면, **Then** 이동한 티켓은 그 두 티켓 사이에 놓이고, 영향을
   받은 다른 티켓들의 순서 정보도 함께 갱신되어 응답에 포함된다.

---

### User Story 3 - 이동에 따른 시작/완료 시각 자동 관리 (Priority: P2)

사용자가 티켓을 할 일 칼럼으로 옮기면 그 순간이 "시작 시각"으로 자동
기록되고, 다시 대기로 되돌리면 시작 시각이 지워진다. 완료 칼럼에 있던
티켓을 다른 칼럼으로 옮기면 완료 시각도 지워져 "아직 완료되지 않음"
상태로 정확히 되돌아간다.

**Why this priority**: 시작/완료 시각의 자동 관리는 사용자가 수동으로
기록할 필요를 없애는 편의 기능으로, 칼럼 이동 자체(User Story 1)가 먼저
동작해야 의미가 있는 부가 가치다.

**Independent Test**: 대기 상태의 티켓을 할 일로 옮긴 뒤 시작 시각이
기록되는지, 그 티켓을 다시 대기로 옮겼을 때 시작 시각이 비워지는지,
완료 상태였던 티켓을 다른 칼럼으로 옮겼을 때 완료 시각이 비워지는지
확인하는 것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 대기 칼럼에 있는 티켓이 있을 때, **When** 사용자가 그
   티켓을 할 일 칼럼으로 옮기면, **Then** 시작 시각이 현재 시각으로
   기록된다.
2. **Given** 할 일 칼럼에 있고 시작 시각이 기록된 티켓이 있을 때,
   **When** 사용자가 그 티켓을 대기 칼럼으로 되돌리면, **Then** 시작
   시각이 비워진다.
3. **Given** 진행 중 칼럼에 있는 티켓을 할 일이 아닌 다른 칼럼(대기)으로
   옮길 때, **When** 이동이 처리되면, **Then** 이미 기록되어 있던 시작
   시각은 변경되지 않는다.
4. **Given** 완료 칼럼에 있던(완료 시각이 기록된) 티켓이 있을 때,
   **When** 사용자가 그 티켓을 다른 칼럼으로 옮기면, **Then** 완료
   시각이 비워진다.

### Edge Cases

- 완료 칼럼으로의 이동 요청: 이 기능은 완료 칼럼으로의 이동을 지원하지
  않는다 — 완료 처리는 별도 기능(완료 처리 기능)의 책임이며, 이 기능에
  완료 칼럼을 대상으로 요청하면 거부된다.
- 이동/재배치 도중 오류가 발생하는 경우: 상태와 순서 변경은 모두 함께
  반영되거나 모두 반영되지 않아야 하며, 일부만 적용된 중간 상태가 남지
  않는다.
- 같은 칼럼, 같은 위치로 "이동"을 요청하는 경우: 오류 없이 처리되며
  결과적으로 순서 변화는 없다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 존재하는 티켓을 대기, 할 일, 진행 중 세 칼럼 중
  하나로, 지정된 위치에 이동시킬 수 있어야 한다.
- **FR-002**: 시스템은 완료 칼럼을 이 기능의 이동 대상으로 허용하지 않아야
  한다.
- **FR-003**: 시스템은 티켓이 할 일 칼럼으로 이동하면 시작 시각을 현재
  시각으로 기록해야 한다.
- **FR-004**: 시스템은 티켓이 할 일 칼럼에서 대기 칼럼으로 이동하면 시작
  시각을 비워야 한다.
- **FR-005**: 시스템은 위 두 경우(FR-003, FR-004)에 해당하지 않는 이동에
  대해서는 기존 시작 시각을 그대로 유지해야 한다.
- **FR-006**: 시스템은 티켓이 완료 칼럼에서 다른 칼럼으로 이동하면 완료
  시각을 비워야 한다.
- **FR-007**: 시스템은 같은 칼럼 내에서 순서만 바꾸는 이동을 지원해야
  하며, 지정한 두 티켓 사이의 위치에 정확히 놓아야 한다.
- **FR-008**: 시스템은 순서 재배치로 인해 다른 티켓들의 순서 정보가 함께
  바뀐 경우, 그 변경 내용을 응답에 포함해야 한다.
- **FR-009**: 시스템은 상태와 순서 변경을 하나의 단위로 처리해야 하며,
  일부만 적용된 상태가 남지 않아야 한다.
- **FR-010**: 시스템은 존재하지 않는 티켓 id로 이동을 요청받으면 티켓을
  찾을 수 없다는 오류를 반환해야 한다.
- **FR-011**: 이동이 성공하면 시스템은 마지막 수정 시각을 현재 시각으로
  갱신해야 한다.

### Key Entities *(include if feature involves data)*

- **티켓(Ticket)**: 001~003에서 정의한 것과 동일한 엔티티. 이 기능은
  티켓의 상태, 칼럼 내 위치, 그리고 파생적으로 시작/완료 시각을 변경한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 드래그앤드롭을 놓는 즉시(1초 이내) 티켓의 새
  위치와 상태가 반영된다.
- **SC-002**: 칼럼 간 이동 시 시작/완료 시각 자동 관리 규칙이 100%
  정확히 적용되어, 사용자가 수동으로 시각을 조정할 필요가 없다.
- **SC-003**: 순서 재배치 요청은 100% 요청한 순서대로 정확히 반영되며,
  동시에 여러 티켓을 이동해도 칼럼 내 순서가 어긋나지 않는다.
- **SC-004**: 존재하지 않는 티켓에 대한 이동 시도는 100% 명확한 "찾을
  수 없음" 오류로 안내된다.

## Assumptions

- 인증/권한 구분이 없는 단일 사용자 환경이므로, 이동은 소유권 확인 없이
  티켓 id만으로 식별된다.
- "완료 칼럼으로의 이동"은 이 기능이 아닌 003-ticket-complete(완료 처리
  기능)의 책임이며, 이 기능은 완료 칼럼을 이동 대상으로 받지 않는다
  (사용자 입력에 명시됨).
- 칼럼 내 위치 지정은 001-board-view가 정의한 position 오름차순 정렬
  규칙과 일관되게 동작한다 — 새 위치는 인접한 두 티켓 사이의 값으로
  계산되며, 필요 시 칼럼 전체 위치값이 재정렬될 수 있다.
- 드래그앤드롭이라는 조작 방식(마우스 동작 자체)은 화면(프론트엔드)의
  책임이며, 이 기능은 "어디서 어디로 옮겼는지"가 확정된 이후의 처리만
  다룬다.
